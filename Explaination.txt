PART 1 — THE PROBLEM WE ARE SOLVING
================================================================

Breast cancer is the most common cancer in women worldwide. In 2024,
over 2.3 million new cases were diagnosed globally. Early detection
is the single most important factor for survival — women diagnosed
at Stage 1 have a 99% survival rate. Women diagnosed at Stage 4 have
only a 28% survival rate.

The primary screening tool is the mammogram — an X-ray of the breast.
Every year, radiologists manually review millions of mammograms looking
for suspicious areas called lesions.

THE HUMAN PROBLEM:
- A radiologist reviews 50-100 mammograms per day
- Each mammogram takes 3-5 minutes to read
- After hours of this, fatigue sets in and errors increase
- Even expert radiologists miss 10-30% of early cancers
- There is a global shortage of radiologists, especially in developing countries

OUR SOLUTION:
Build an AI that automatically looks at a mammogram image and:
1. Draws a box around any suspicious area (lesion detection)
2. Says what type it is (classification)
3. Works in under 1 second, without fatigue, consistently

This is called Computer-Aided Detection (CAD). Our specific approach
uses deep learning object detection — the same technology that powers
self-driving cars and face recognition.

PART 2 — THE DATASET: CBIS-DDSM
================================================================

We use CBIS-DDSM (Curated Breast Imaging Subset of DDSM).

WHAT IT IS:
- A public dataset of real mammogram X-ray images from hospitals
- Collected and organized by Lee et al. (published in Nature Scientific Data)
- The gold standard benchmark for mammogram AI research
- Over 1,000 published papers have used this exact dataset
- Available free from Kaggle (kaggle.com)

WHAT IT CONTAINS:
- 2,620 mammography studies from 1,566 patients
- Both MASS and CALCIFICATION lesion types
- Expert radiologist annotations showing EXACTLY where each lesion is
- Pathology labels (BENIGN, BENIGN_WITHOUT_CALLBACK, MALIGNANT)
- ROI (Region of Interest) masks — pixel-level drawings of each lesion

TWO TYPES OF LESIONS:
1. MASS — A solid lump or density. Feels like a lump. Can be any shape.
   - Benign mass: Usually round/oval with smooth edges (e.g., cyst, fibroadenoma)
   - Malignant mass: Usually irregular, spiculated edges (classic sign of cancer)

2. CALCIFICATION — Tiny calcium deposits, seen as bright white spots.
   - Benign calc: Large, scattered, smooth shapes (e.g., milk of calcium)
   - Malignant calc: Tiny, irregular, clustered (classic sign of ductal carcinoma)

OUR DATASET STATISTICS:
- Total valid records loaded: 3,567
- Class 0 (benign_mass):       912 images
- Class 1 (malignant_mass):    784 images
- Class 2 (benign_calc):     1,198 images
- Class 3 (malignant_calc):    673 images

HOW WE SPLIT THE DATA:
We divided into 3 sets:
- Training set (2,190 images = 70%) → AI studies these, adjusts its weights
- Validation set (455 images = 15%) → Used during training to check progress
- Test set (458 images = 15%) → Locked away, only used for final evaluation

CRITICAL DESIGN DECISION — PATIENT-LEVEL SPLIT:
Most papers use RANDOM split — just randomly assign images to train/val/test.
This is WRONG for medical data and causes "data leakage":
- The same patient might have images in both training AND test
- The AI learns patient-specific features (breast density, tissue texture)
- This makes results look better than they really are
- Real-world: the AI will see NEW patients it has never seen

WE USE GROUPSHUFFLESPLIT BY PATIENT ID:
- If Patient P001's left breast is in training, their RIGHT breast CANNOT be in test
- All images from the same patient stay in the same split
- This is methodologically rigorous and reviewers appreciate it

CODE USED FOR SPLITTING:
gss1 = GroupShuffleSplit(n_splits=1, test_size=0.30, random_state=42)
→ Splits by patient groups, ensuring no patient crosses splits

PART 3 — THE AI MODEL: YOLO11
================================================================

WHAT IS YOLO?
YOLO = You Only Look Once. A family of object detection AI models
created by Ultralytics. Originally designed to detect objects like
cars, people, and animals in real-time video.

KEY INSIGHT: Instead of looking at each part of an image separately,
YOLO looks at the ENTIRE image once and predicts ALL objects simultaneously.
This is why it is extremely fast (milliseconds per image).

HOW YOLO WORKS (simplified):
1. Image goes in → divided into a grid
2. Each grid cell predicts: "Is there an object here? Where? How big? What class?"
3. Non-max suppression removes duplicate predictions
4. Output: bounding boxes with class labels and confidence scores

YOLO VERSION HISTORY:
- YOLOv1 (2016) → First version, proof of concept
- YOLOv3-v5 → Widely adopted for real applications
- YOLOv8 (2023) → Major architecture upgrade, 43.6M parameters
- YOLO11 (October 2024) → Latest version, 25.3M parameters, more efficient

WHY YOLO11 SPECIFICALLY?
1. It was released in October 2024 — very recent
2. Very few medical imaging papers have used it yet — early advantage
3. More efficient than YOLOv8 (25.3M vs 43.6M parameters) with competitive accuracy
4. Better architecture for small object detection (important for tiny calcifications)

THE MODEL WE CHOSE — YOLO11l:
YOLO11 comes in 5 sizes: n (nano), s (small), m (medium), l (large), x (extra-large)
We chose YOLO11l (large) because:
- Big enough to learn complex mammogram features
- Small enough to train within Kaggle's 30-hour GPU limit
- 25.3 million parameters, 87.3 GFLOPs computational cost
- Previously pretrained on COCO (1.2M natural images) — gives it base visual knowledge

TRANSFER LEARNING:
We do NOT train from scratch. YOLO11l already "knows how to see" from COCO.
We FINE-TUNE it on mammograms — teaching it specifically about lesions.
This is like taking a doctor with general medical knowledge and giving them
specialized radiology training. It is much faster and requires less data.

PART 4 — HOW WE PREPARED THE DATA (TECHNICAL)
================================================================

THE CHALLENGE:
CBIS-DDSM stores lesion locations as MASK IMAGES (pixel drawings of the lesion).
YOLO needs BOUNDING BOXES (4 numbers: center_x, center_y, width, height).
We had to convert one to the other.

OUR PIPELINE:
Step 1: Find the CSV files (mass_case_description_train_set.csv, etc.)
Step 2: For each row, find the matching JPEG mammogram image
Step 3: Find the matching ROI mask image
Step 4: Read the mask with OpenCV (computer vision library)
Step 5: Find contours (outlines) in the mask using findContours()
Step 6: Get bounding rectangle of the largest contour
Step 7: Convert to YOLO format (normalized center_x, center_y, width, height)
Step 8: Write to .txt file alongside the image

PATH RESOLUTION PROBLEM:
The CSV files contain DICOM paths (medical image format paths).
The actual files are JPEGs with different folder structures.
We built a 3-tier resolution system:
- Level 0: Look by folder name
- Level 1: Look by grandparent/parent folder combo
- Level 2: Look by patient ID + view (CC/MLO)
This ensures we find 99%+ of images correctly.

AUGMENTATION STRATEGY (MEDICAL-SPECIFIC):
Standard augmentation (designed for natural photos) can HURT medical images.
We customized:
- mosaic=0.0 (OFF) → Mosaic mixes 4 images together — bad for mammograms
  because it distorts the breast anatomy and creates unrealistic images
- copy_paste=0.3 → Copies lesions from one image to another
  Why: gives the model more examples of rare lesion types
- flipud=0.5 → Random vertical flip
  Why: A lesion in the upper breast vs lower breast should be detected equally
- fliplr=0.5 → Random horizontal flip
  Why: Left breast vs right breast — same lesions, mirror image

TRAINING CONFIGURATION:
- Optimizer: AdamW (adaptive learning rate, weight decay prevents overfitting)
- Learning rate: 0.0005 starting, decays to 0.000005 (cosine schedule)
- Warmup: 10 epochs (model slowly increases learning rate at start)
- Batch size: 4 (limited by GPU memory at 1024px image size)
- Image size: 1024×1024 pixels
- Mixed precision: AMP FP16 (trains faster using 16-bit instead of 32-bit math)
- Early stopping: patience=30 (stops if no improvement for 30 epochs)
- Max epochs: 150 (upper limit, early stopping usually triggers first)
- Hardware: Kaggle Tesla T4 GPU (14.9GB VRAM)

EXPERIMENTS 6-8 — SPECIALIST MoE APPROACH (NEW — June 2026)
================================================================

APPROACH: Instead of one model for all lesions, train SPECIALIST models.
This is called Mixture of Experts (MoE):
- Mass Expert: only detects benign_mass and malignant_mass
- Calc Expert: only detects benign_calc and malignant_calc

RATIONALE: Masses and calcifications are fundamentally different objects.
Forcing one model to detect both may hurt performance on each individually.
Specialist models can focus all capacity on one lesion type.

DATASET SPLIT FOR SPECIALIST MODELS:
Mass Expert training:
  Train: 1,103 images | Val: 241 images | Test: 248 images

Calc Expert training:
  Train: 871 images | Val: 177 images | Test: 180 images

TRAINING CONFIG (same for all specialist experiments):
  Model: YOLO11l (25.3M parameters)
  Image size: 1024×1024
  Epochs: 150 max, patience=30 (early stop)
  Optimizer: AdamW, lr0=0.0005, cos_lr=True
  Warmup: 10 epochs
  Augmentation: copy_paste=0.3, flipud=0.5, fliplr=0.5, mosaic=0.0
  Hardware: Tesla T4 GPU (Kaggle)

PART 7 — METRICS EXPLAINED (FOR PAPER WRITING)
================================================================

BOUNDING BOX:
When the model detects a lesion, it draws a box: [x_center, y_center, width, height]
These are normalized (0 to 1) relative to image dimensions.

IoU (Intersection over Union):
- Measures how much our predicted box overlaps with the expert's drawn box
- IoU = 1.0 → perfect overlap
- IoU = 0.5 → boxes overlap by 50%
- We use IoU=0.5 as our threshold (standard in object detection)

PRECISION:
Of all the boxes the model drew, what fraction were correct?
- Precision = True Positives / (True Positives + False Positives)
- Our precision: 0.39 means 39% of predicted boxes contain real lesions

RECALL (SENSITIVITY):
Of all real lesions, what fraction did the model find?
- Recall = True Positives / (True Positives + False Negatives)
- Our recall: 0.58 means model finds 58% of all real lesions

WHY RECALL MATTERS MORE IN MEDICINE:
- False Negative (missed cancer) → patient goes untreated → potentially fatal
- False Positive (false alarm) → extra test ordered → anxiety, cost, but no harm
- In cancer screening: we prefer HIGH RECALL even if precision drops

MALIGNANT RECALL (CLINICAL KEY METRIC):
- YOLO11l malignant recall: 0.661 → model finds 66.1% of malignant lesions
- YOLOv8l malignant recall: 0.703 → model finds 70.3% of malignant lesions
- This is the NUMBER ONE clinical metric we report in the paper

F1 SCORE:
F1 = 2 × (Precision × Recall) / (Precision + Recall)
Harmonic mean — balances precision and recall.
Used when you care about both equally.

mAP50:
Mean Average Precision at IoU=0.50
The PRIMARY metric in object detection papers.
Computed by: for each class, plot Precision-Recall curve, calculate area under curve.
Then average across all classes.

mAP50-95:
Mean Average Precision averaged across IoU thresholds from 0.50 to 0.95
More strict — the box must overlap MORE with ground truth to count as correct.
Lower than mAP50 but more informative about box quality.

PART 8 — TECHNICAL PROBLEMS WE SOLVED DURING THE PROJECT
================================================================

PROBLEM 1: Kaggle GPU Quota Exceeded
Original account ran 38h 48min out of 30h weekly limit.
Solution: Created a new Kaggle account with different email + phone verification.

PROBLEM 2: Session Expiry Without Save
Kaggle sessions run for max 9-12 hours. Training ran for 11+ hours.
Session expired before Save Version was clicked. Weights were lost.
Solution: Now click Save Version immediately when EarlyStopping fires.

PROBLEM 3: Dataset Path Resolution
CSV files use DICOM paths. Actual files are JPEGs with different folder structure.
Example: CSV says "/CBIS-DDSM/Mass-Training_P_01988/1.3.6.../000000.dcm"
But file is at "/kaggle/input/.../P_01988/08-14-2016/1.3.6.../000000.jpg"
Solution: Built 3-tier JPEG index system that finds files by:
- Folder name (level 0)
- Grandparent/parent combo (level 1)
- Patient ID + view (level 2)

PROBLEM 4: Multiple Lesions Per Image
Some mammogram images have 2-3 lesions (from different exam views or multiple findings).
The CSV has multiple rows for the same image.
Solution: GroupBy image path, write ALL bboxes to the same label file.
One image → one label file → multiple lines (one per lesion).

PROBLEM 5: Duplicate Labels Warning
YOLO prints "N duplicate labels removed" during dataset scanning.
This happens when the same image appears in multiple CSV rows and our
groupby creates duplicate bbox entries.
Solution: These warnings are harmless — YOLO automatically removes exact duplicates.
Does NOT affect training quality.

PROBLEM 6: Data Contamination (Exp 5)
First aborted run created 300 images in /kaggle/working/yolo_cbis/.
Second full run added 2190 images to same directory.
Result: Val and test folders had ~693 images (300+455 and 235+458) mixed.
Solution: We re-ran Exp 3 eval on clean 458-image test set (verified).
Exp 5 eval was on contaminated 693-image set — noted as limitation.

PROBLEM 7: Exp 4 Weights Not Saved
The original Exp 4 training completed (mAP50=0.1836) but Save Version
was not clicked in time. Weights not in committed output.
Solution: Re-ran Exp 4 training completely from scratch on new account.

PROBLEM 8: IndentationError in Copy-Paste Code
Copying code from chat interface corrupts Python indentation (tabs vs spaces).
Solution: Split code into smaller cells. Use simple string writing instead
of complex dict/yaml formatting that breaks across lines.

PROBLEM 9: data.yaml Disappeared After GPU Switch
Switching accelerator (None → GPU T4) restarts the Kaggle kernel.
/kaggle/working/ is CLEARED on kernel restart.
Solution: Always rebuild dataset after kernel restart before running eval.

PROBLEM 10: Original Account GPU Quota
Original account had 51:09 remaining shown — but session wouldn't start.
Reason: That showed cumulative quota used (51h), not remaining time.
Solution: Created second new account for Exp 5, used third notebook
for Exp 3/4 re-evaluation.
